## 3. プロジェクト概要（500字以内）
このプロジェクトは、ものづくりの現場で熟練者に集中している暗黙知を、作業動画から「分かれ目」の判断カードにして、次の世代へ渡すWebアプリです。

作者は自動車系企業の試作部署で働いています。図面上で成り立つものでも、現場では加工の難しさや品質のばらつきが壁になり、それを越える技能は引退間近の熟練者に集中しています。暗黙知とは、ここが分かれ目だと気づくことと、そこでどちらを選ぶかです。

登録者は、考えを声に出しながら作業を撮るだけです。Claudeが文字起こしから判断カードと成功・失敗の分岐図を下書きし、何を見るか、境界、加減、理由、守らないとどうなるかに分解します。知識や数値はAIが根拠つきで補い、体感や状況の判断は熟練者の言葉を主役にします。熟練者が確かめて承認したものだけが教材になります。

学ぶ側は、動画つき手順書、ショート動画、並べ替えと分かれ目のクイズで学び、自分のトライ動画をお手本と比べられます。題材は家庭の3Dプリンターでのサポート設定です。

## 7. 開発中に一番詰まった場面
①何を作ろうとしていましたか？
試作の現場で働く私が、引退していく熟練者の「あの人にしか分からない」を次の世代へ残すアプリです。熟練者の横で見て真似ても同じ品質にはならず、本人に聞いても、うまく言葉にならない。現場でずっと感じてきたこの悔しさを、形にしたいと思いました。最初は、作業動画から「正しい手順書」を作ろうとしていました。

②Claude にどのように指示しましたか？
作業動画から手順とコツをまとめるように頼みました。そのうえで、「カンコツって結局何なのか」「試作は毎回やることが変わるのに、手順を残す意味はあるのか」と、現場で感じていることをそのまま日本語でぶつけました。

③何が起きましたか？
きれいな手順は出てきます。でも、それを読んでも、若手が明日からできるようになる気がしませんでした。試作は毎回ゼロスタートで、治具も材料も案件ごとに変わります。Claude の答えが悪いのではなく、私自身が「本当に残すべきものは何か」を言葉にできていないと気づき、開発の序盤で手が止まりました。

④期待していた結果と何が違いましたか？
手順書ができれば技能も伝わると期待していました。実際に伝わるのは手順だけで、熟練者が「どこを見て、なぜそうして、どこで止めたか」という判断は抜け落ちたままでした。

④どのように対処しましたか？
手順を追いかけるのをいったんやめて、自分の思いつきを Claude Code と一緒に分解し直しました。たどり着いたのは、暗黙知とは技そのものより「ここが分かれ目だと気づくこと」と「そこでどちらを選ぶか」だ、という答えです。分かれ目を「何を見るか、正常と異常の境界、加減、止める条件、守らないとどうなるか」などに分け、判断を知識・数値・体感・状況の4種類に整理して、AIが答えてよいことと熟練者にしか語れないことの線を引きました。AIは勝手に決めず、熟練者が承認した言葉だけを教材にする。この考えを文書に残してアプリの芯にすると、判断カード、分岐図、教育モードが一本につながりました。

## 10. Claude を使った感想と改善してほしい点
**利点**
- プログラミングは少ししかできないが、日本語で「こうしたい」と伝えるだけで、画面・データベース・AIの呼び出しまで1週間で作れた。
- 「熟練者の判断」という言葉にしにくい考えを、一緒に整理して仕組みに落とし込めた（判断モデル）。

**欠点**
- 専門用語が多く、初心者には説明が難しいことがある。「短く、一つずつ」と頼むと改善した。
- 長い作業の途中で会話の容量がいっぱいになり、前の内容をまとめ直す必要があった。docs に決めたことを書き戻して乗り切った。

**比較**：比較なし（今回は Claude のみで開発）

**一つだけ直すなら**：スマホの実機での動き（音・自動再生・指の操作）を確かめる手段がもっと欲しい。手元のiPhoneで直接試して結果を受け取れれば、現場の人が使う道具をもっと短い時間で仕上げられる。
