# 提出用メモ（提出文・デモ動画で使う素材）

## 作者の肩書き

**採用：自動車試作エンジニア**

- 過去の受賞記事は「弁護士が」「心臓内科医が」のように、**短い肩書き＋何を作ったか**の形。それに合わせて肩書きは飾らず短くする。
- 「現場にいる人が、現場の課題から作った」ことが一言で伝わる（審査「インパクト：課題の出どころ」）。
- 「エンジニアだが本職のプログラマーではない」ことも伝わる。過去の受賞者も多くがこの立場。

紹介文の形（案）：
> 自動車試作エンジニアが、図面に載らないカンコツを若手に引き継ぐために作った。

- 暗黙知を表す言葉は「図面に載らないカンコツ」を第一候補にする（応募文の「図面上で成立しても実現の壁がある」とつながる）。ほかの候補：「マニュアルにできない手加減」「言葉にならない勘所」。

場面に応じた言い換え：
- 「3Dプリンタで車の樹脂部品をつくる試作担当」… 作業内容を具体的に見せたいとき（家庭の3DPの題材とつながる）
- 「ものづくりの現場から来た、ほぼ未経験のビルダー」… 「Python少しでもClaude Codeでここまで作れた」を強調したいとき
- 「猫の給餌機を自作した、試作現場の技術者」… デモ動画の自己紹介など、人柄を出したいとき

注意：
- 社名・具体的なメーカー名は公開リポジトリと動画では書かない。必要なら「自動車メーカー系の試作部署」程度にとどめる。

## 参考：過去の Claude Code ハッカソン受賞作品の共通点

出典：Anthropic 公式ブログ（Built with Opus 4.6 / Opus 4.7 の受賞者紹介記事）。審査員の講評は載っていないため、以下は記事から読み取った傾向。

- **作者自身の仕事・生活の深い課題**（弁護士→建築許可、医師→研修医の練習、修理職人→基板診断、大工の息子→修理診断、工場技術者→保全）。4.6回は受賞5人中4人が本職の開発者ではない。
- **使う人がはっきりしていて、実際に使われ始めている**（自治体の導入検討、医学部での試験運用など）。
- **作る前に仕様と計画に時間をかける**。助言：「よく考えてから作る」「評価を先に、機能は後」「Claudeに監査させる」「モデルに反論する」。
- **試行錯誤を数字で示す**（コミット数、テスト数、熟練者との一致率 74%→81% など）。
- **最終日はデモ動画に充てる**（思ったより時間がかかる）。

ツールの使い方の共通点：
- 作業を分けて並行で進める（Claude Code のセッションを複数開く、分野ごとにエージェントを置く）。
- Claude を画像や映像の理解に使う（道路映像、回路図、修理箇所の写真）。
- 熟練者の知識を整理したデータ（JSONなど）にして毎回 Claude に渡す。
- Skills・Managed Agents・MCP を目的に合わせて選ぶ。
- 入力チェックやプロンプトインジェクション対策など、安全面も作り込む。

本作品に特に近い例：**MaestrIA**（大工の父への聞き取り→知識ファイル化→父の判断との一致率で評価）、**ARIA**（工場の熟練技術者の判断を保全に活かす）。
