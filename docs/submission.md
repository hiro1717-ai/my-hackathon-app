# 提出用メモ（提出文・デモ動画で使う素材）

## 作者の肩書き

**採用：自動車試作技能員**

**決定した紹介文：**
> 自動車試作技能員が、図面に載らない熟練者にしかない暗黙知を引き継ぐ。

（以下は決定までの検討メモ）

- 過去の受賞記事は「弁護士が」「心臓内科医が」のように、**短い肩書き＋何を作ったか**の形。それに合わせて肩書きは飾らず短くする。
- 「現場にいる人が、現場の課題から作った」ことが一言で伝わる（審査「インパクト：課題の出どころ」）。
- 「エンジニアだが本職のプログラマーではない」ことも伝わる。過去の受賞者も多くがこの立場。

紹介文の形（案）：
> 自動車試作エンジニアが、図面に載らないカンコツを若手に引き継ぐために作った。

- 暗黙知を表す言葉は「図面に載らないカンコツ」を第一候補にする（応募文の「図面上で成立しても実現の壁がある」とつながる）。ほかの候補：「マニュアルにできない手加減」「言葉にならない勘所」。

場面に応じた言い換え：
- 「3Dプリンタで車の樹脂部品をつくる試作担当」… 作業内容を具体的に見せたいとき（家庭の3DPの題材とつながる）
- 「ものづくりの現場から来た、ほぼ未経験のビルダー」… 「Python少しでもClaude Codeでここまで作れた」を強調したいとき
- 「猫の給餌機を自作した、試作現場の技術者」… デモ動画の自己紹介など、人柄を出したいとき

注意：
- 社名・具体的なメーカー名は公開リポジトリと動画では書かない。必要なら「自動車メーカー系の試作部署」程度にとどめる。

## 参考：過去の Claude Code ハッカソン受賞作品の共通点

出典：Anthropic 公式ブログ（Built with Opus 4.6 / Opus 4.7 の受賞者紹介記事）。審査員の講評は載っていないため、以下は記事から読み取った傾向。

- **作者自身の仕事・生活の深い課題**（弁護士→建築許可、医師→研修医の練習、修理職人→基板診断、大工の息子→修理診断、工場技術者→保全）。4.6回は受賞5人中4人が本職の開発者ではない。
- **使う人がはっきりしていて、実際に使われ始めている**（自治体の導入検討、医学部での試験運用など）。
- **作る前に仕様と計画に時間をかける**。助言：「よく考えてから作る」「評価を先に、機能は後」「Claudeに監査させる」「モデルに反論する」。
- **試行錯誤を数字で示す**（コミット数、テスト数、熟練者との一致率 74%→81% など）。
- **最終日はデモ動画に充てる**（思ったより時間がかかる）。

ツールの使い方の共通点：
- 作業を分けて並行で進める（Claude Code のセッションを複数開く、分野ごとにエージェントを置く）。
- Claude を画像や映像の理解に使う（道路映像、回路図、修理箇所の写真）。
- 熟練者の知識を整理したデータ（JSONなど）にして毎回 Claude に渡す。
- Skills・Managed Agents・MCP を目的に合わせて選ぶ。
- 入力チェックやプロンプトインジェクション対策など、安全面も作り込む。

本作品に特に近い例：**MaestrIA**（大工の父への聞き取り→知識ファイル化→父の判断との一致率で評価）、**ARIA**（工場の熟練技術者の判断を保全に活かす）。


## プロジェクト名（候補）
短く、何をするか分かり、検索で被らないもの。
1. **カンコツ** … 現場の言葉そのまま。一番覚えやすい。
2. **分かれ目** … アプリの芯（判断モデル）そのもの。審査員に仕組みが伝わりやすい。
3. **ワカレメ** … 2 のカタカナ。見た目が軽く、Z世代向けの画面と相性がよい。
4. **カンコツカード** … 判断カードが主役であることが伝わる。
5. **AI技能コーチ** … 今の仮名。説明的だが平凡。

おすすめ：**「分かれ目」**（副題：熟練者のカンコツを動画から判断カードにする）。

## デモ動画 3分の構成（案）
審査「デモ 25%：冒頭で課題と解決策、前提知識なしで価値が分かるか」に合わせ、最初の20秒で全部言う。

| 時間 | 場面 | 画面 | 言うこと |
|---|---|---|---|
| 0:00〜0:20 | 課題と答え | 作者の顔 or 3DPの手元 | 「試作は毎回ゼロスタート。熟練者が早いのは、図面に載らない分かれ目を知っているから。それを動画1本から判断カードにして、若手が自分で作れるようにするアプリです」 |
| 0:20〜0:45 | 撮るだけ | スマホで撮影→送る | 「熟練者は作業しながらしゃべって撮るだけ」。文字起こし→静止画が出る画面 |
| 0:45〜1:20 | AIの下書き | 料金の確認→カード一覧 | 「有料処理は必ず料金を見せて確認。Claude が20項目のカードを下書き。分かれ目・安全・判断の種類（A知識/B数値/C体感/D状況）を付け、言っていないことは書かずに質問に回す」 |
| 1:20〜1:45 | 承認 | カード画面、しゃべって答える、書き戻し | 「熟練者は合ってる／直すだけ。質問にはしゃべって答える。答えは欄に書き戻される」 |
| 1:45〜2:15 | 使う | 参照モード（検索→動画の場面）、ショート動画風 | 「若手は必要なコツだけ10秒で引く。Z世代にはショート動画風」 |
| 2:15〜2:40 | 教育モードと導線 | 分かれ目で止まる→答える→熟練者の答え。失敗から逆引き | 「新人は分かれ目で止められて考える。失敗したら『波打った』で逆引き」 |
| 2:40〜3:00 | 評価と締め | 完成品の写真比較→指摘→逆引きへ。最後にリポジトリ | 「完成品を基準と比べ、違いから分かれ目に戻る。試作現場に限らず、分野プロファイルを足せば調理・介護にも。全部ローカルで動き、外に出るのはカードの下書きだけ」 |

撮り方：画面録画（Mac の QuickTime でスマホ画面をミラー、または Mac のブラウザをスマホ幅で）＋ナレーションは後録り。冒頭の20秒だけ実写（3DPの手元）。

## Claude の使い方（質問への回答の下書き）
- **アプリの中**：Claude API（Opus 5.5）に、文字起こし・静止画・案件情報・分野プロファイルを一緒に渡し、構造化出力（JSONの形を先に決める）で判断カード20項目を下書き。確度の門番（言っていない欄は空にして質問に回す）、分かれ目マーカー、判断の4種類、安全判定。Sonnet 5.5 で質問の答えを欄に書き戻し。Opus 5.5 で完成品写真を基準と比較（断定しない）。有料処理は全て確認画面＋円の予想＋実費表示。
- **開発**：Claude Code デスクトップアプリで、仕様の一問一答（docs/spec.md に逐次書き戻し）→ 実装 → ブラウザ操作で動作確認 → 画面写真 → コミット、を小さく回した。作者は Claude Code 初心者で Python 少し。
- **仕組みの工夫**：分野プロファイルを md で持つ（Skills の考え方。md を足す＝分野を足す）。コミット前フックで秘密情報の混入を止める。Claude に `.env` を読ませない拒否ルール。
- **数字**：コミット数、判断カードの下書き1回の料金（31秒の動画で約12円）、large-v3 の所要時間（動画の約2.5〜3倍）、など。
