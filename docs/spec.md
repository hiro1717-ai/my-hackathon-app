# アプリ仕様（2026-11-04 整理版）

> 状態：仕様の骨格は決定。残りは「未決事項」を参照。判断の芯は `docs/judgment.md`、題材の背景は `docs/domain.md`。

## 1. 一言で
ベテランが**作業を動画に撮るだけ**で、アプリがその作業のカンコツ（暗黙知）＝**素人とベテランの分かれ目**を読み取り、**新人でもその作業ができる動画手順書**にするツール。
今回は3Dプリント試作を題材にするが、本体は**業務分野ごとにカスタマイズできる作業分析ツールの基盤**。

## 2. 目的（迷ったらここに戻る）
- 技術・技能を暗黙知・属人化にしない。**誰でも簡単にやれること**が目的。
- ベテラン・中堅は、やり方（段取りと判断の理由）が分かればやれる → すぐ引ける形で残す。
- 新入社員に教育の人手を割きづらい → **アプリを見れば、人に教わらなくても現場で作業できる**のが理想。教育モードは座学ではなく「現場で作業しながら見る手順書の初心者向けの見せ方」。
- ただの学習アプリではない。**分かれ目を見つけ、判断を分解して残す**という、他に代替できない判断基準を持つ（`docs/judgment.md`）。
- 数値化されていないカンコツも、**データの蓄積とともに徐々に言語化・数値化していく**アプリにする。

## 3. 背景（作者の問題意識）
- **試作の現場は毎回ゼロスタートが基本。自動車の試作に限らず、一品物・オーダーメイド・多品種少量生産の全般に共通する。治具も設備も材料も工法も、案件ごとに全部変わる。** 標準の手順がないので、量産向けの「ムダを見つける」作業分析は効かない。
- それでも熟練者には、これまでこなしてきた知見から**早く・安くやり切る方法**がある。昔の試作は手作業が多く、削る・曲げる・合わせる・直すを何百回も繰り返す中で「分かれ目」の気づきを体で積み上げてきた。設備や図面が変わっても通用するのは、それが「手順」ではなく「判断」として身についているから。
- 設備の進歩やDXで手作業は昔ほど必要なくなった。その結果、**若手がベテランと同じ気づきを得る機会が今の時代にはほとんどない**。設備や図面で解決できない場面は今も残り、引退間近の熟練者に集中している。技術は衰退し、気づきと学びの機会は失われつつある。
- 現場では技能伝承（ベテランの作業指導、見よう見まね）を試みているが、同じ品質にならない。「どこを見て、なぜそうして、どこで止めたか」は目に映らないから。できても何倍もの工数とコストがかかり、試作として成り立たない。「ベテランに頼む」か「若手が時間をかけて低品質に作る」かの二択になっている。
- このアプリは、その悩みに対して**分かれ目を見つけ、本人の言葉で残し、次の試作を効率化する**。ムダを見つけるAIではなく、分かれ目を残すAI。
- 試作や中小企業のオーダーメイド的な仕事（多品種少量生産）には「全部に効く万能ツール」がない。
- 試作品が変わるたびに段取りをやり直す。お金で設備やアプリを買っても解決しない。効率化に限界があり現場は疲弊し、イノベーションが起きにくい。
- だからこそ「人の技術・技能」が要。その暗黙知を減らす・解決することがテーマ。

## 4. 誰のためのものか（レベル別）
| レベル | 立場 | 使い方 |
|---|---|---|
| ベテラン | 知っていることを出す人 | 撮ってしゃべるだけ。下書きを確認・承認。負担は最小 |
| 中堅 | やれるが説明できない人 | **参照モード**：必要なカードをすぐ引く。自分のやり方との違いも見られる |
| 新入社員・若手 | やり方を見ただけではやれない人 | **教育モード（必須）**：分かれ目で動画が止まり「次にどうする？なぜ？」。教わる人がいなくても現場で作業できる |
| （将来）設計者 | 現場の工夫を設計に生かす人 | 加工しにくい箇所や工夫の一覧 |

## 5. 判断モデル（芯。詳細は `docs/judgment.md`）
- カンコツ＝**分かれ目**。「ここが分かれ目だと気づけること」と「そこでどちらを選ぶか」。
- 分かれ目1個は7つに分解できる：①何を見ているか ②正常／異常の境界 ③選択肢と選び方 ④行動と加減 ⑤止める条件／次へ移る条件 ⑥重みづけ・配分 ⑦素人がやるとどうなるか。
- 測れるもの（温度・トルク・時間・角度）は数値で残す。測れないもの（力・感触）は「身近な例え」「結果の状態」「強すぎ・弱すぎの失敗」で挟む（judgment.md 4c、決定）。
- 判断には4種類：**A 知識**（AIが高確度）／**B 数値**（AI＋センサー）／**C 体感**（ベテランの言葉と映像でしか残らない）／**D 状況**（判断の筋道を残す）。
- 経験の差＝見てきた「状態の数」。異常・失敗の事例を溜めて新人に先に見せる。
- **蓄積→言語化・数値化**：同じ分かれ目のカードが溜まるほど、Cの「軽く」「少し傾ける」に数値（例：15°〜30°）が紐づき、CからBへ昇格していく。アプリは「数値化できそうな候補」を示す。

## 6. 分野プロファイル（基盤としての仕組み）
- 3DP試作は分野プロファイルの1実例。製造・設計・調理・介護などに応用できる基盤。
- プロファイルの中身：動画を読む観点／起きやすい失敗・不具合／安全の観点（熟練者優先）／聞き取りの定型質問（判断モデル①〜⑦から生成）／段階の区切り方（3DPなら 設計→印刷→後処理、調理なら 仕込み→加熱→盛り付け）。
- 業種名で固定せず、**仕事を分ける軸6本**の組み合わせで組み立てる：
  1. クリエイティブ側／オペレーション側
  2. 相手がモノか人か
  3. 繰り返しか一品物か
  4. 判断の手がかり（目／手／耳／味・匂い／相手の反応）
  5. 失敗の重さ（やり直せる／やり直せない・危険）
  6. 段取り主体か手技主体か
- 例：3DP試作＝オペレーション側（設計の段取り含む）／モノ／一品物／目＋手／失敗は軽い／段取り主体。調理＝オペレーション／モノ／繰り返し／味・匂い・目／軽い／手技主体。介護＝オペレーション／人／毎回違う／相手の反応／重い／状況判断主体。
- 実装では Claude Code の **Skills**（分野ごとの知識ファイル）として持つ。

## 7. 題材（決定）：3Dプリントで試作部品を1点作る
- 車の樹脂部品の試作で3DPを使う。それを家庭の3DPに置き換え、作者が自分で手を出せる形にした。勤務先の素材・情報は使わない。熟練者役は作者本人。
- 3段階：**1 設計の段取り**（穴位置、工具が入るか、ボルト締め構造）→ **2 印刷の設定**（向き・角度・サポート・意匠面・壊れやすい向き。不具合が起きやすい状態も再現して残す）→ **3 後処理**（したい加工に対して必要な工具・物・手順）。
- MVPは**オペレーション側が主役**。設計の段取りは「作る前のチェック手順」として取り込む。将来はクリエイティブ側にも対応（データの形は共通）。
- 3DPは B（数値：オーバーハング45°など）と C（体感：当て板で傷を防ぐ）が混ざった題材。AI提案と熟練者の役割分担を見せやすい。

## 8. データの骨格
```
熟練者（レベル1〜7）───────────┐ 動画・カードの出どころとして紐づく
分野プロファイル（3DP試作／調理／介護…）
 └ マニュアル（試作部品1点：最終的にしたい形・用途）
    └ 段階（1 設計の段取り → 2 印刷の設定 → 3 後処理）
       └ 手順ごとの判断カード（分かれ目1個＝1枚）
          └ 紐づく動画・写真の場面（失敗品の写真、手元映像）
```

## 9b. 熟練者レベル（1〜7）と重み（決定）
- 動画を登録する人にレベル1〜7を持たせ、その人の動画から出たカードはレベルに応じた重みで参考にする。
- 目安（案）：1 初心者／2 一人でできる／3 一通り任せられる／4 中堅（人に教えられる）／5 ベテラン（難しい案件を任せられる）／6 熟練（社内で頼られる）／7 匠（業界レベル）。
- 効く場面：
  - 同じ手順で複数の熟練者の判断が食い違う → 高レベルを優先し、低レベルは「別のやり方」として併記。
  - 教育モードで新人に見せる優先順位。
  - AI提案の確度 × 熟練者の重み で「このカードの確からしさ」を出す。
- レベルは管理者（会社側）が付ける想定。MVPでは登録時に自己申告で入力。

## 9c. 人によって手順が違う問題（決定）
- 順番が違っても同じ分かれ目を扱っていることがある。カードを「どの分かれ目か」で突き合わせ、人が違っても同じ分かれ目なら同じカードの「別のやり方」としてまとめる。
- **全員がやっている分かれ目＝その作業の本質。人によって違う所＝流派。** 本質を先に新人に教える。
- 順番そのものが重要な場合がある。各カードに「前提（この手順の前に必要なこと）」（項目18）と「順番を変えると何が起きるか」（項目19）を持ち、順番が重要なカードは順番ごと教える。
- 実装：複数熟練者比較ビュー（共通の分かれ目／流派／順番の違い）。MVPでは熟練者1人なので、データの形だけ備える。

## 9d. 導線（成功の導線／失敗の導線）（決定）
分かれ目を順につないだ道筋。カードの項目4（判断）・8（素人がやると）・9（失敗）・18（前提）・19（順番）・20（波及先）を線でつなぐだけで出せる。
- **成功の導線**：各分かれ目でベテランの判断を選び続けた道。承認済みカードを順に並べたもの。
- **失敗の導線**：どこかの分かれ目で素人の選択に入り、失敗に至る道。失敗が後の工程へ波及する線も引く。
- 使い方：
  1. 作る前に全体を眺める（分かれ目はいくつ、戻れないのはどれ）
  2. **失敗から逆引き**：「面が波打った」と言うと、失敗の導線をさかのぼり「どの分かれ目でどっちに入ったか」の原因候補を示す。「何がわからないかわからない」への直接の答え
  3. 教育モードで新人が選んだ答えを導線上に点で置く（「ここで失敗側に入った」）
  4. ベテラン自身の分析：失敗の導線が薄い所＝説明が足りない所＝聞き取りが足りない所
- 表示はMVPに入れる（簡易な分岐図でよい）。波及先はClaudeに1回聞いて下書き。逆引きはClaude 1回で症状と承認済みカードを照らす。

## 10. 知識の出どころ（決定）
- 主役は熟練者の知識（C・D）。AIは下書き・質問・「さらに良くするには」の**確度の高い提案（A・B）**のみ。確度の低いことは出さない（出すなら「未確認」）。
- **A（知識）のうち、その会社・現場にしかないローカル知識**（社内規格、この機械のクセ、得意先の好み）は外に出ていないので、**熟練者を優先**。AIは一般知識（規格・公開情報）だけを根拠つきで出す。
- 優先順位：**安全 ＞ ローカル知識 ＞ 熟練者の体感・状況判断 ＞ AIの一般知識・数値**。
- **安全に関わることは熟練者を優先**。
- 共通ルール：**AIは確度の低い情報を持ってこない**。根拠を示せないものは出さない。
- 出どころをラベルで区別する（項目14）。熟練者とAIの相乗で、学ぶ人がベテラン以上に育つ可能性もねらう。

## 11. 入力：ベテランは撮るだけ（決定）
- **作業しながら説明をしゃべる動画**が基本。音声の文字起こしがカンコツの主な材料。映像は場面を示す役（物の認識ではなく「なぜ」を読む＝「画像解析」とは違う）。
- アプリが手順に切り分け、判断カードの下書きを作り、読み取れなかった欄だけ短く聞く。承認されたものだけが手順書になる。
- **読み取りは総合で行う（決定）**。材料：しゃべり（なぜ・加減・止める条件）／映像のコマ（道具・手元・対象物の状態・作業の切り替わり）／時刻と時間配分／案件の情報（材料・用途・最終形）／分野プロファイル（観点・失敗・安全）／ベテランが足した写真と回答／過去のカード。
- 映像は「道具と状態を確かめる」ために使う。動きを解析してムダや姿勢を判定することはしない（画像解析との線引き）。
- 将来は無言の動画にも対応し、しゃべった分だけ精度が上がる設計。
- **動画は縦型が基本**（スマホで撮ってそのまま）。横向きに撮ったものは回転して扱えればOK。

## 12. 出力：動画で見れる手順書（決定）
- 手順がチェックリスト型に並び、各手順を開くと動画（または写真）が再生され、横に判断カードが出る。
- **参照モード**（中堅・ベテラン）：迷った1点だけ確認する使い方。手順名・カードの検索から1タップで届く「探しやすさ」が命。動画は頭からではなく、そのカードの数秒だけ再生。
- **教育モード**（新入社員、必須）：分かれ目で動画が止まり「次にどうする？なぜ？」。答えを判断カードと照らして振り返りを返す。「いま止める？まだ？」（項目7）も問える。
- 余裕があれば：「この手順について聞く」窓（承認済みカードを根拠に答える）。主役にはしない。

## 13. UIは2種類、切り替え可能（決定）
作る側はガラケー世代、見る側はZ世代を想定。同じデータを、切り替えボタン1つで行き来。作る場面・見る場面とも切り替え可能。
- **Z世代向け：ショート動画風** — 縦全画面動画、上スワイプで次の手順、要点を字幕のように重ね、タップで「なぜ？」。教育モードでは動画が止まって選択肢。撮る側は縦に撮ってそのまま投稿する感覚。
- **ガラケー世代向け：1画面1操作** — 選ぶものは1〜3個、大きな文字・ボタン、番号付き手順、「次へ」「戻る」は常に同じ場所、縦スクロールとタップだけ。録画ボタン1つ、確認は「合ってる／直す」。目安は「LINEくらいの操作感」。

## 14. 機能一覧
### 残す（ベテラン）
1. **マニュアルを登録**：作る物の説明・写真。分野プロファイルを選ぶ。
2. **撮る**：録画ボタン1つ。作業しながらしゃべる。
3. **読み取り（自動）**：文字起こし → 手順の切り分け → 判断カード16項目の下書き → 分かれ目マーカー → 判断の種類タグ → 足りない欄の質問。
4. **聞き取り**：足りない欄だけ、判断モデル①〜⑦から生成した短い質問（「どうなったら止める？」「素人がやるとどうなる？」）。しゃべって答える。
5. **確認・承認**：カード1枚ずつ「合ってる／直す」。AIの改善提案は「採用／不採用」。失敗写真を足す。
### 使う：参照モード（中堅・ベテラン）
6. **やり方を引く**：マニュアル → 段階 → カード＋動画の場面。
7. **配分ビュー**：各手順にベテランがかけた時間の割合（項目15から自動）。
8. **自分のやり方と比べる**：「自分ならこうする」との違いを整理（余裕があれば）。
### 使う：教育モード（新入社員）
9. **分かれ目で止めて問う**：「次にどうする？なぜ？」「いま止める？まだ？」。答えをカードと照らして振り返り。
10. **異常状態ライブラリ**：作業前に失敗・異常の写真と言葉を見る（経験の差を疑似的に埋める）。
11. **振り返り**：自分の作業の記録・映像をカードと照らす（余裕があれば）。
### 自分で分析する（全員）
16. **導線ビュー**：成功の導線／失敗の導線を分岐図で表示。失敗からの逆引き、新人の選択の重ね表示（9d）。
17. **完成品の評価**：新人が完成品を6面（正面・背面・右・左・上・下）撮り、マニュアル登録時にベテランが指定した「測る箇所」の寸法を手入力。AIがベテランの完成品写真と同じ構図で並べ、外観・形状の違い（サポート跡・傷・反り・層割れ・糸引き・ゆがみ）を箇所ごとに指摘（絶対評価ではなく比較。はっきりしない所は「要確認」、不良と断定しない）。寸法は公差と照らす。結果を「完成品記録」としてマニュアルに残し、違いがあれば失敗の導線を逆引きして原因候補の分かれ目を返す。記録が溜まれば「新人が落ちやすい分かれ目」が見え、分かれ目マーカーと教育モードに返る。
    - 写真の撮り方をそろえる工夫：①ゴースト重ね（撮影画面にベテランの完成品写真を半透明で重ね、輪郭を合わせて撮る。最も効く）②方眼の台紙（5mm方眼＋向き印を敷き、台紙ごと回す。傾き補正・寸法の目安・色の基準）③6面ウィザード（1面ずつ案内、順番固定）④撮った瞬間のチェック（ブレ・暗さ・はみ出し・ゴーストとのズレで撮り直しを促す）⑤同じ場所・同じ光をマニュアルで決める ⑥将来：動画で1周撮って6面を切り出す。
    - ベテランもマニュアル登録時に同じ画面で完成品の6面を撮る（これが基準になる）。
    - **評価ポイント（寸法）の決め方**：マニュアル登録時に平面の三面図（正面・側面・上面）をアップロードできる。AIが図面から寸法の候補を拾い、ベテランが「要所・評価ポイントになる寸法」を確認して選ぶ（公差も）。図面がないマニュアルは、テキストボックスで「測る箇所・目標値・許容範囲」を手入力して設定する。
    - **評価モードは分野ごとに差し替える**：上記は「図面を元に部品を作る業界」向けの評価モード（外観比較＋寸法）。飲食（盛り付け・火の通り・味の記録）、介護（相手の状態・安全）などは評価の仕方が違うので、分野プロファイルの一部として評価モードを今後追加する方針。MVPは図面ベースの評価モードのみ。
    - MVP：正面＋意匠面＋問題が出やすい面の3面、寸法1〜2箇所、ゴースト重ねまで。6面・④⑤は余裕があれば。
### 蓄積して育てる（全員）
12. **次のマニュアルへの引き継ぎ**：似た過去カードを提示。「毎回ゼロから」を減らす（余裕があれば）。
13. **数値化の候補**：同じ分かれ目のカードが溜まったら、体感の言葉に数値を紐づけ、C→Bへ昇格を提案（将来。MVPでは「候補」の表示まで）。
14. **複数熟練者の突き合わせ**：同じ分かれ目を人をまたいでまとめ、本質／流派／順番の違いを見せる（将来。MVPではデータの形だけ）。
15. **分野プロファイルの追加**：Skillを足す＝分野を足す。2例目（調理など）を薄く入れて基盤を証明。
### MVP（3分で見せる太い線）
2 撮る → 3 読み取り → 5 承認 → 6 参照 → 9 教育モード → 16 導線ビュー（簡易）→ 17 完成品の評価（3面・簡易）。UI切り替えと導線を見せ場に。7は追加コストが小さいので入れる。8・11・12・13は余裕があれば。

## 15. 使用例（給餌機のフタ部品）
1. ベテランが録画して作業しながらしゃべる。送信して終わり。
2. アプリが文字起こし → 手順に切り分け → カード下書き → 分かれ目マーカー。足りない欄だけ質問を残す。
3. 翌朝5分で確認。「合ってる／直す」、質問にはしゃべって答える。AI提案は「採用」。
4. 新人が教育モードで開く。分かれ目で動画が止まり「どの向きで印刷する？なぜ？」。答えると振り返り。ベテランに聞かずに1個作れる。
5. 中堅は参照モードで必要なカードだけ10秒で引く。

## 16b. 技術構成（決定。ローカル運用が前提）
方針：将来はできる限りローカル運用。外部サービスは使わず、Python のライブラリとモデルのインストールで済む形にする。外部は Claude API だけ（将来ローカルモデルに差し替えられる作りにする）。

| 役割 | 使うもの | 外部 |
|---|---|---|
| Python 本体 | 3.12 を `uv` で入れる（Mac 標準の 3.9 は使わない） | なし |
| アプリ本体 | FastAPI ＋ 素の HTML / JavaScript（Jinja テンプレート） | なし |
| データ | SQLite（1ファイル） | なし |
| 動画・写真・図面 | Mac 内のフォルダ `media/`（git には入れない） | なし |
| 文字起こし | faster-whisper をローカルで。**本番・デモ素材は large-v3（最良）**、開発中は small。設定1つで切替 | なし |
| 映像のコマ | ffmpeg（pip で入る `static-ffmpeg`）で、文字起こしの区切り時刻と数秒ごとに静止画を切り出す | なし |
| AI | Claude API（anthropic ライブラリ）。カードの構造化はツール使用、静止画・完成品写真・図面は画像入力。読み取りは Opus 5.5、軽い処理は Sonnet 5.5 | **あり** |
| スマホからの利用 | 同じ Wi-Fi で Mac の住所（http://192.168.x.x:8000）を開く。撮影はスマホのカメラアプリ → アップロード | なし |
| 公開URL | 不要。提出はデモ動画＋リポジトリ。必要になったら一時的なトンネルで対応 | — |

開発機：Intel Core i5・メモリ8GB・空き6.4GB（2026-11-05 時点）。large-v3 は軽量化版で約1.6GB、4分動画で20〜40分見込み。送信して放っておく運用。

取り下げた案：Next.js／Vercel／Supabase／ブラウザ内録画＋Web Speech API（外部サービス依存と https の手間のため）。

## 16c. 実装済み（11/5 時点）
- 撮る→送る→文字起こし（faster-whisper、small / large-v3 を画面で選択、分野の用語ヒント）→静止画→**判断カードの下書き（Claude Opus 5.5、構造化出力）**まで自動。
- 承認画面：1枚ずつ「合ってる／直す／不採用」。足りない欄の質問に「しゃべって答える」（ブラウザの音声認識、サーバーに送らない）。
- 参照モード：承認済みカードを手順順に、配分ビュー、言葉で探す、分かれ目に成功／失敗の導線、失敗から逆引き（文字照合）。
- 教育モード：分かれ目で動画が止まり「次にどうする？なぜ？」→熟練者の答え→合っていた／違っていた を記録。異常状態ライブラリ。
- 分野プロファイルは `app/profiles/3dp.md`（md を1枚足す＝分野を足す）。
- 質問への答えを AI（Sonnet 5.5）が欄に書き戻す（確認画面つき、1〜2円）。
- 完成品の評価（MVP）：測る箇所の登録（目標値±許容）、熟練者の基準写真3面、学ぶ人の写真3面＋寸法、ゴースト重ね（選んだ写真に基準を半透明で重ねて構図確認）、寸法はローカルで判定、写真の違いは Claude が面ごとに「同等／要確認／違いあり」（断定しない）、症状語から参照モードの逆引きへ。
- UI切替：参照モードに「ショート動画風」（縦全画面、上スワイプで次の手順、場面だけ繰り返し再生、要点を字幕風に重ね、「なぜ？」で開く）。端末ごとに好みを覚え、「ふつうの画面」で戻せる。
- **有料処理（Claude API）は自動で走らせない**。必ず確認画面で円の予想（幅つき）を見せ、「はい」で実行。実行後は使ったトークン数から実費を計算して画面に残す（決定）。文字起こし（Whisper）はローカルで無料。

## 18. 決定事項（まとめ）
- テーマ「あなたにしかない深さを」。勤務先の情報・映像は使わない。Streamlit は使わない。
- 題材：3Dプリントで試作部品を1点作る（設計の段取り→印刷の設定→後処理）。熟練者役は作者本人。
- 基盤アプリ：分野プロファイル（仕事を分ける軸6本）で差し替え可能。MVPはオペレーション側が主役。
- 判断モデル：分かれ目の7分解、判断の4種類（A〜D）、蓄積→言語化・数値化。
- 「案件」をやめて**マニュアル**と呼ぶ（2026-11-07）。トップは「マニュアル一覧」。管理者が作る**フォルダー（1段だけ）**で分けて並べる。**マニュアル番号＝フォルダー記号＋3桁の連番**（例：3DP-001、未分類は M-001）を作った時に振り、フォルダーを移しても変えない（管理者は手で直せる）。一覧に検索（題名・ゴール・番号・熟練者）と絞り込み（フォルダー・熟練者・レベル以上・承認済みの手順の有無）。内部の表名・URL は昔のまま `projects`。
- 判断カード20項目＋分かれ目マーカー。成功／失敗の導線を分岐図で出し、失敗から逆引きできる。
- 完成品の評価：6面写真＋手入力寸法をベテランの完成品と比較。評価ポイントは三面図のアップロードから拾う（図面がなければテキストで設定）。評価モードは分野ごとに差し替え（MVPは図面ベースのみ）。ゴースト重ね・方眼台紙・ウィザードで撮り方をそろえる。結果はマニュアルに残し、導線の逆引きと蓄積に使う。熟練者レベル1〜7で重み付け。順番の重要度と前提を持ち、人による手順の違いは「同じ分かれ目」で突き合わせる。
- 入力：作業しながらしゃべる**縦型**動画（横向きは回転でOK）。文字起こし必須。アプリが読み取り、足りない所だけ聞く。チャットは主役ではない。
- 出力：動画で見れる手順書。参照モード／教育モード（必須）。
- UI：Z世代向けショート動画風／ガラケー世代向け1画面1操作、切り替え可能。
- 知識の出どころ：熟練者が主役。AIは確度の高い提案のみ。安全は熟練者優先。出どころをラベルで区別。
- 公開URLで誰でも触れる形。コードは GitHub 公開リポジトリ。言語は問わない（作者は Python 少し）。
- 技術：ローカル運用。Python 3.12（uv）＋ FastAPI ＋ SQLite ＋ faster-whisper（large-v3）＋ ffmpeg ＋ Claude API。公開URLは不要、スマホは同じ Wi-Fi から。
- できた部分から画面録画してデモ素材に。**デモ動画は3分**。
- 安全の表示（2026-11-07）：一覧では緑の「安全」の印だけを付ける。**いま作業中（再生中・表示中）の安全カードだけ、枠を緑で点滅**させる（動画画面・参照モード・ショート画面）。
- カードを手で足す＝**場面を区切って足す**（2026-11-07）：種類は 🟠カンコツ（分かれ目）／🟢安全の説明／手順。時間が重なるカードは自動で前後に分ける（真ん中に入れると元のカードと「続き」の2枚になる）。ほかのカードを丸ごと隠す範囲は受け付けない。カード画面から「この中を区切って別のカードにする」で入れる。AIの下書きを作り直しても手で足したカードは残る。
- 管理者の動画一覧（2026-11-07）：各マニュアル・各動画に「入って直す」ボタン。押すとマニュアル登録モードで開き、熟練者と同じように直せる。
- 動画の指操作（2026-11-07、すべての動画プレイヤー）：右を2回タップ＝10秒送る／右を0.5秒以上長押し＝押している間だけ2倍速。左は逆（10秒戻す／2倍速で巻き戻し）。真ん中と下の操作バーはふつうに使える。「⏹ 止める」ボタンは作らないことにした。
- 構成（2026-11-07 確定）：フォルダー（管理者が作る分類）→ マニュアル（例：給餌機のフタ。ゴール・熟練者を持つ）→ 作業（動画1本ごと。作業名＝動画の名前。中に判断カード）。マニュアルの編集欄で、名前・作業名・ゴールをまとめて直せる。
- モードの呼び名（2026-11-07）：「熟練者／若手」→「**マニュアル登録／マニュアル閲覧**」。マニュアルの画面：上に「作業の動画」（熟練者）、下に「トライ動画（閲覧・登録）」（学ぶ人）を分けて並べ、それぞれ名前で探せる。トライ動画を送る欄はその一番下（両モード）。
- 「フォルダー」は「**分類**」と呼ぶ（2026-11-07）。印は 🏷️（📁はマニュアルと紛らわしいのでやめた）。マニュアルを作るとき・マニュアルの編集で、分類を選ぶか「＋新しい分類を作る」でその場で作れる（記号は空なら C, C1… と自動）。並べ替え・消すは管理者メニュー。
- 動画編集モード（管理者、2026-11-07）：分類 → マニュアル → 動画の順に並べる。分類・種類・言葉で絞り込める。マニュアルごとに「🏷️分類を変える」（新しい分類も作れる）、動画ごとに名前の保存。サムネイル（✏ 直す）を押すと登録モードで開いて全部直せる。
- 編集画面（2026-11-07）：マニュアルの編集は専用の画面（/projects/{id}/edit：名前・作業名・ゴール・熟練者・分類・番号・消す）。編集画面と、登録モードの動画・カード画面は**背景を薄い黄色**にして「✏ 編集中」と出す。動画編集モードの鉛筆は、マニュアル→編集画面、動画→動画の画面（カードを直す）へ。
- ゴールは**作業（動画）ごと**に持つ（2026-11-07）。videos.goal。今あったマニュアルのゴールは各作業に写した。作業を入れるときに作業名・ゴールを書け、編集画面と動画画面の設定で直せる。AIの下書きは、その作業のゴールを使う。

- ID・パスワードの保存は1つのボタン「💾 IDとパスワードを保存」にまとめた（2026-11-08）。空欄の項目はそのまま（パスワード空欄＝変えない）。
- パスワードの表示（2026-11-08）：保存は元に戻せない形（ハッシュ）のまま。管理者が管理者メニューでパスワードを変えた直後だけ、画面の上に「🔑 ○○の新しいパスワード」を1回表示する（サーバーのメモリだけで、アドレスにもDBにも残さない。再読み込みで消える）。
- ID・パスワードを忘れたとき（2026-11-08。メールは使わず、口頭で伝える）：①ログイン画面「ID・パスワードを忘れた」→ 名前（必須）とID（分かれば）で申請。②管理者が🔔→「ID・パスワード再設定の申請」で、名前・IDが合う候補から本人のアカウントを選び、伝えるIDを決めて（空欄なら今のID）「認めてIDとワンタイムパスワードを配る」。画面に1回だけ出るIDと6桁のワンタイムパスワードを本人に口頭で伝える（ワンタイムパスワードはハッシュで保存）。③本人はログイン画面「パスワードを再設定する」で、ID・ワンタイムパスワード・新しいパスワードを入れる（24時間有効・1回で終わり・5回間違えたら使えない）。まだ決めていない申請が30件を超えたら受け付けない。
- 呼び方：設定画面（👤 アカウント）は「表示名」、それ以外の画面（ID忘れの申請・管理者のユーザー一覧）は「名前」。

- 教育モードの刷新（2026-11-08。前の「分かれ目で止まって問う」形は置き換え。前の学んだ記録は残す）：
  0. 見る（/learn）：承認済みの手順の場面を順番に通して流す。いつでも「テストへ進む」。
  1. 並べ替え（/learn/order）：ランダムに並んだ手順カードを、長押しでつかんで動かし（まわりはぬるっと動く）、正しい順番に。答え合わせで違うカードが赤く揺れる。正解するまでやり直し。
  2. 安全ポイント（/learn/safety）：正しい並びの手順から、安全ポイントの手順をすべてタップ（○・×・見落とし）。正解したら、安全ポイントごとに「守らないとどうなる？」を書き、お手本（気をつけること・守らないと）と見比べる（AIは使わない）。安全ポイントがないマニュアルは飛ばす。
  3. 分かれ目（/learn/branch）：分かれ目の手順をすべてタップ。○×を出し、間違えたところに解説（分かれ目の理由・守らないと・見るところ）。全部正解で「🏅 教育完了」。
  - 全部正解したら learn_completions に残す（やり直し回数3つと、書いた答え）。👤 アカウントの「🏅 教育完了履歴」に出る。管理者は ⚙ 管理者メニュー →「🏅 教育完了履歴（ユーザー検索）」で、名前・IDで探して全員分（書いた答えも）を見られる。
  - 途中の回数・答えは、その端末のブラウザ（sessionStorage）に一時的に持つ。
