# アプリ仕様（たたき台）

> 状態：**検討中**。決まったら「未決事項」から「決定事項」へ移す。

## 一言で
ベテランが**作業を動画に撮るだけ**で、アプリがその作業のカンコツ（暗黙知）を読み取り、**新人でもその作業ができる動画手順書**にするツール。技術・技能を暗黙知・属人化にしないことが目的。
今回は3Dプリント試作を題材にするが、本体は**業務分野ごとにカスタマイズできる作業分析ツールの基盤**。

## 基盤アプリとしての位置づけ（決定）
- 3Dプリント試作は「分野プロファイル」の1実例。本体は、あらゆる製造・設計・飲食店の調理・介護などの業務に応用できる基盤モデル。
- 分野ごとに「**判断材料の基盤情報**」を差し替える＝**分野プロファイル**：
  - 動画を読むときに何に注目するか（観点）
  - 起きやすい失敗・不具合
  - 安全の観点（ここは熟練者優先）
  - 聞き取りの定型質問
  - 手順の段階の区切り方（3DPなら 設計→印刷→後処理、調理なら 仕込み→加熱→盛り付け など）
- 企業ごとに、その会社の作業に合ったオリジナル分析ツールへ近づけられる構造にする。
- 飲食の例：凝ったレシピを考える仕事と、同じレシピでも「その人が作ると美味しくなる」過程の専門性は別物。後者こそ動画から読み取る対象。
- 分野プロファイルは業種名で固定せず、**仕事を分ける軸の組み合わせ**で組み立てる（軸は下記）。
- 実装では分野プロファイルを Claude Code の Skills（分野ごとの知識ファイル）として持つ案が有力（「Claudeの活用」の説明にもなる）。

## 仕事を分ける軸（分野プロファイルの部品）
| 軸 | 分かれ方 | なぜ効くか |
|---|---|---|
| 1. クリエイティブ側／オペレーション側 | 設計者・レシピ考案者 ↔ 製作者・調理者（現場側） | 創る側は「何を作るか」、形にする側は「どう作るか」の判断。聞き取りの質問が違う |
| 2. 相手がモノか人か | 製造・調理 ↔ 介護・接客・看護 | 人が相手だと相手の状態で判断が変わる。手順書より「状況→判断」の形。安全の重みも違う |
| 3. 繰り返しか一品物か | 量産・定番 ↔ 試作・オーダーメイド | 一品物は毎回「段取り」から考える。繰り返しは手技の精度が主 |
| 4. 判断の手がかり | 目／手／耳／味・匂い／相手の反応 | 動画と音声で拾えるものが決まる。味や感触は本人の言葉でしか残らない |
| 5. 失敗の重さ | やり直せる ↔ やり直せない・危険 | 安全優先のルールと、教育モードで「止めて問う」場所に効く |
| 6. 段取り主体か手技主体か | 前に決める ↔ その場の手の動き | 聞き取りを作業前にするか作業中にするか |

例：
- 3Dプリント試作（今回）：形にする側（設計の段取りも含む）／モノ／一品物／目＋手／失敗は軽い／段取り主体
- 飲食・調理：形にする側／モノ／繰り返し／味・匂い・目／失敗は軽い／手技主体
- 介護：形にする側／人／毎回違う／相手の反応／失敗は重い／状況判断主体

## MVPの範囲：まずはオペレーション側（決定）
- MVP（最小限で価値が伝わる試作版）は**オペレーション側（現場で作る人）を主役**にする。
- 「設計データはある。それを壊れず・きれいに・手間なく作るには」を動画手順書にする。
- 設計の段取り（工具が入る？ボルト締めできる？）は「作る前のチェック手順」としてオペレーション側に取り込む。
- 将来はクリエイティブ側（設計・レシピ考案）にも対応し、**両軸で使える**基盤にする。データの形は両側で共通にしておく。

## ベテランの入力は「撮るだけ」（決定）
- ベテランは作業を撮るだけ。**作業しながら説明をしゃべる動画を基本にする**（決定）。チャット形式で作業するのが主役ではない。
- 音声の文字起こしがカンコツの主な材料。映像はその場面を示す役。物の認識（画像解析）ではなく「なぜそうしたか」を読み取ることで、参加者ガイドの「作らないもの（画像解析）」と区別する。
- 将来は無言の動画にも対応し、しゃべった分だけ精度が上がる設計にする。
- アプリが動画（と音声）から手順を切り出し、「何を見て、どう判断し、どう加減したか」を読み取って下書きする。
- 読み取れなかった部分だけ短く聞く（例：「ここで一度止めたのはなぜ？」）。
- ベテランが直して承認すると、動画の該当場面に紐づき、新人が見る手順書になる。

## 判断カードの役割
動画を手順書にするための「暗黙知1個ぶんの箱」。ベテランが書くものではなく、アプリが動画から読み取った下書きをベテランが直す。**動画 → 判断カード → 手順書** の真ん中にある単位。名前は現場に合う言葉（カンコツ、ポイント等）に変えてよい。

## 目的（判断に迷ったらここに戻る）
- 「教える」ことが目的ではない。**誰でも簡単にやれること**が目的。
- ベテラン・中堅は、やり方（段取りと判断の理由）が分かればやれる → すぐ引ける形で残す。
- 初心者・若手は、やり方を見ただけではやれない → 順を追って練習できる形も用意する。
- 教えること自体も重要。ただし**新入社員に教育の人手を割きづらい**。だから理想は「**アプリを見れば、人に教わらなくても現場で作業できる**」こと。教育モードは座学ではなく、現場で作業しながら見る手順書の「初心者向けの見せ方」と考える。

## 背景（作者の問題意識。ここから外れない）
- 試作や中小企業のオーダーメイド的な仕事（多品種少量生産）には、設備・アプリ・ノウハウのどれにも「全部に効く万能ツール」がない。
- 試作車種や試作品が変わるたびに、それに合わせて生産の準備（段取り）をやり直す必要がある。
- お金で設備やアプリを買っても解決しない。だから効率化には限界があり、現場は疲弊している。
- 通常業務に割く時間が増え、イノベーションが起きにくい。
- だからこそ「人の技術・技能」が要になる。その技能の中身（暗黙知）を減らす、あるいは解決することがテーマ。

## 誰のためのものか（レベル別）
| レベル | 立場 | アプリでの使い方 |
|---|---|---|
| **ベテラン** | 知っていることを出す人 | 聞き取りに答え、まとめを確認・承認する。負担は最小にする |
| **中堅** | やれるが説明できない人 | **参照モード**：段取りと判断の理由をすぐ引いてやる。自分のやり方との違いも見られる |
| **初心者・若手** | やり方を見ただけではやれない人 | **教育モード**：同じ手順書を、理由・映像・確認問いつきで一歩ずつ表示。教わる人がいなくても現場で作業できるのが理想 |
| （将来）設計者 | 現場の工夫を設計に生かす人 | 加工しにくい箇所や工夫の一覧を見る |

## 残す暗黙知の2層
- **A. 手の技能**：ヤスリの当て方、はんだの流し方など、体でやる部分。映像に映る。
- **B. 段取りの判断**：新しい試作品を前に「どの順で、どの工具で、どこまでの精度で、どこに気をつけて作るか」を決める部分。映像に映りにくいが、「毎回ゼロから準備する」疲弊の正体に近い。
- 方針：**Bを主にしてAも含める**（仮）。一つの試作品について「どう作るか決める→実際に作る」を一続きで聞き取る。

## 題材（決定）：3Dプリントで試作部品を1点作る
給餌機の自作で作者が苦労した経験をもとに、「一品物の試作部品を設計→印刷→後処理する」一連の仕事を題材にする。
勤務先の素材を使わずに、試作現場の「設計→加工→仕上げ」の縮図を語れる。熟練者役は作者本人。

暗黙知は3段階に分かれる：
| 段階 | 判断の例（暗黙知） |
|---|---|
| **1. 設計の段取り** | 穴位置の決め方、この構造で工具が入るか、ボルト締めできる構造か、最終的にどういう形にしたいか |
| **2. 印刷の設定** | どの向き・角度で印刷するか、サポートをどうするか、意匠面はどちら向きか、この角度だと壊れやすい。**不具合が起きやすい状態も再現して残す** |
| **3. 後処理** | 「こういう加工にしたい」という目的に対して、どんな工具・物・手順が必要か |

ゴール：この3段階を満たして、**誰でも簡単に作業を完了できる**AIアプリ。

## アプリの骨格：「案件（試作部品1点）」を単位にする
```
案件（何を作るか：最終的にしたい形・用途）
 └ 段階（1 設計の段取り → 2 印刷の設定 → 3 後処理）
    └ 手順ごとの判断カード      ← 注目点・判断・加減・理由・失敗するとどうなる
       └ 写真・映像の該当場面   ← 失敗品の写真、後処理の手元映像など
```

## 知識の出どころ（決定）
- **主役は熟練者の知識**：聞き取りと承認で引き出したものが「やり方」の本体。
- **AIの知識は下書きと補助**：聞き取りの質問を作り、まとめの下書きを出す。
- **「さらに良くするには」**：AIが**確度の高い情報だけ**を改善提案として添える。根拠と確度を明示し、採用するかは熟練者が決める。確度の低いことは出さない（出すなら「未確認」と明示）。
- ねらい：熟練者の知識とAIの知識を相乗させれば、学ぶ人がベテラン以上に成長できる可能性もある。
- **安全に関わることは熟練者の知識を優先する**。AIの提案が熟練者の判断と食い違う場合、安全面では熟練者を採る。
- 判断カードには**出どころのラベル**を付ける：「熟練者の判断」／「AIの提案（承認済み）」。どこまでが人の暗黙知で、どこからがAIの補足かを見えるようにする。

## 手順書の形（決定）：動画で見れる手順書
- 手順が「設計の段取り → 印刷の設定 → 後処理」の順に並ぶ（チェックリスト型）。
- 各手順を開くと、**その手順の動画（または写真）が再生**され、横に判断カード（注目点・判断・加減・理由・失敗例）が出る。
- 参照モード（中堅・ベテラン）：動画と判断カードをそのまま引く。
- 教育モード（新入社員）：動画が判断の直前で止まり「次にどうする？なぜ？」と問い、答えを判断カードと照らして振り返りを返す。
- 余裕があれば：「この手順について聞く」窓（承認済みの判断カードを根拠にClaudeが答える）。主役にはしない。

## 主役にする流れ（ここが独自性）
暗黙知の聞き取り → 熟練者の確認 → 案件に紐づく「やり方」 → 参照／練習
（映像の分析やチャットは手段であって主役ではない）

## 機能案
### 残す（ベテランが使う）
1. **案件を登録**：作る物の説明や写真を入れる。
2. **段取りの聞き取り**：Claudeが「まず何から？」「なぜその順？」「ほかの選び方は？」「失敗するとしたらどこ？」と掘り下げ、段取り表の下書きを作る。
3. **作業映像の聞き取り**：映像を場面に分け、「ここで何を見ていた？」「どう加減した？」と手の技能を聞き取り、手順に紐づける。音声があれば文字起こしして材料にする。
4. **確認・承認**：Claudeがまとめた判断カードを直して承認する。本人が認めたものだけが「やり方」になる。

### 使う：参照モード（中堅・ベテランが使う）
5. **やり方を引く**：案件を開くと、段取り表と手順ごとの判断カード（＋映像の場面）がすぐ見られる。
6. **自分のやり方と比べる**：「自分ならこうする」を入れると、承認済みの判断カードとの違いをClaudeが整理する。

### 使う：教育モード（初心者・若手が使う）
7. **練習する**：手順の直前で止まり「次にどうする？なぜ？」と問う。答えを判断カードと照らして振り返りを返す。
8. **振り返る**：自分がやった作業の記録や映像を入れ、判断カードと照らして「どこで違ったか」を返す。

### 全員に効く（背景の課題に直接効く）
9. **次の案件への引き継ぎ**：新しい案件を登録すると、過去案件の似た判断カードを提示する。「毎回ゼロから」を減らす。

### MVP（3分で見せる太い線。仮）
2（段取りの聞き取り）→ 4（承認）→ 5（参照）→ 7（教育モード）。6・8・9 は余裕があれば。
**教育モード（新入社員向け）は必ず実装する**（決定）。

### 余裕があれば
- 設計・作業方法へのフィードバック（加工しにくい箇所や工夫の一覧）

## 決定事項
- テーマは「あなたにしかない深さを」を想定。
- 勤務先の情報・映像は使わない。家庭で撮れる作業または利用許可のある素材のみ。
- Streamlit は使わない。
- MVPは**オペレーション側（現場で作る人）が主役**。クリエイティブ側は将来対応（両軸で使える基盤にする）。
- 基盤アプリ：3DPは分野プロファイルの1実例。分野ごとに判断材料の基盤情報を差し替えられる構造にする。
- ベテランの入力は「撮るだけ」。アプリが動画から読み取り、足りない所だけ聞く。チャットは主役ではない。
- 手順書の形：**動画で見れる手順書**（手順ごとに動画＋判断カード。教育モードでは動画が止まって問う）。
- 知識の出どころ：熟練者の知識が主役。安全に関わることは熟練者を優先。AIは下書き・質問・「さらに良くするには」の確度の高い提案のみ。出どころをラベルで区別する。
- **題材は「3Dプリントで試作部品を1点作る」**（設計の段取り→印刷の設定→後処理）。熟練者役は作者本人。詳細は上の「題材」。
- 新入社員向けの**教育モードは必ず実装する**。「アプリを見れば現場で作業できる」が理想。
- 作者のプログラミング経験：Python を少しだけ。言語は問わない（Claude Code が書く前提で選ぶ）。
- アプリの形：**公開URLで誰でも触れる形**にする。コードは GitHub の公開リポジトリにまとめる。形式はハッカソンに提出できれば何でもよい。
- 動画は**作業しながら説明をしゃべる形**を基本にする。音声の文字起こしは必須（カンコツの主な材料）。
- 進め方：できあがった部分から順に画面録画しておき、デモ動画の素材にする。
- **デモ動画は3分**。機能や画面はすべて「3分で伝わるか」で判断する。
