# アプリ仕様（2026-11-04 整理版）

> 状態：仕様の骨格は決定。残りは「未決事項」を参照。判断の芯は `docs/judgment.md`、題材の背景は `docs/domain.md`。

## 1. 一言で
ベテランが**作業を動画に撮るだけ**で、アプリがその作業のカンコツ（暗黙知）＝**素人とベテランの分かれ目**を読み取り、**新人でもその作業ができる動画手順書**にするツール。
今回は3Dプリント試作を題材にするが、本体は**業務分野ごとにカスタマイズできる作業分析ツールの基盤**。

## 2. 目的（迷ったらここに戻る）
- 技術・技能を暗黙知・属人化にしない。**誰でも簡単にやれること**が目的。
- ベテラン・中堅は、やり方（段取りと判断の理由）が分かればやれる → すぐ引ける形で残す。
- 新入社員に教育の人手を割きづらい → **アプリを見れば、人に教わらなくても現場で作業できる**のが理想。教育モードは座学ではなく「現場で作業しながら見る手順書の初心者向けの見せ方」。
- ただの学習アプリではない。**分かれ目を見つけ、判断を分解して残す**という、他に代替できない判断基準を持つ（`docs/judgment.md`）。
- 数値化されていないカンコツも、**データの蓄積とともに徐々に言語化・数値化していく**アプリにする。

## 3. 背景（作者の問題意識）
- 試作や中小企業のオーダーメイド的な仕事（多品種少量生産）には「全部に効く万能ツール」がない。
- 試作品が変わるたびに段取りをやり直す。お金で設備やアプリを買っても解決しない。効率化に限界があり現場は疲弊し、イノベーションが起きにくい。
- だからこそ「人の技術・技能」が要。その暗黙知を減らす・解決することがテーマ。

## 4. 誰のためのものか（レベル別）
| レベル | 立場 | 使い方 |
|---|---|---|
| ベテラン | 知っていることを出す人 | 撮ってしゃべるだけ。下書きを確認・承認。負担は最小 |
| 中堅 | やれるが説明できない人 | **参照モード**：必要なカードをすぐ引く。自分のやり方との違いも見られる |
| 新入社員・若手 | やり方を見ただけではやれない人 | **教育モード（必須）**：分かれ目で動画が止まり「次にどうする？なぜ？」。教わる人がいなくても現場で作業できる |
| （将来）設計者 | 現場の工夫を設計に生かす人 | 加工しにくい箇所や工夫の一覧 |

## 5. 判断モデル（芯。詳細は `docs/judgment.md`）
- カンコツ＝**分かれ目**。「ここが分かれ目だと気づけること」と「そこでどちらを選ぶか」。
- 分かれ目1個は7つに分解できる：①何を見ているか ②正常／異常の境界 ③選択肢と選び方 ④行動と加減 ⑤止める条件／次へ移る条件 ⑥重みづけ・配分 ⑦素人がやるとどうなるか。
- 判断には4種類：**A 知識**（AIが高確度）／**B 数値**（AI＋センサー）／**C 体感**（ベテランの言葉と映像でしか残らない）／**D 状況**（判断の筋道を残す）。
- 経験の差＝見てきた「状態の数」。異常・失敗の事例を溜めて新人に先に見せる。
- **蓄積→言語化・数値化**：同じ分かれ目のカードが溜まるほど、Cの「軽く」「少し傾ける」に数値（例：15°〜30°）が紐づき、CからBへ昇格していく。アプリは「数値化できそうな候補」を示す。

## 6. 分野プロファイル（基盤としての仕組み）
- 3DP試作は分野プロファイルの1実例。製造・設計・調理・介護などに応用できる基盤。
- プロファイルの中身：動画を読む観点／起きやすい失敗・不具合／安全の観点（熟練者優先）／聞き取りの定型質問（判断モデル①〜⑦から生成）／段階の区切り方（3DPなら 設計→印刷→後処理、調理なら 仕込み→加熱→盛り付け）。
- 業種名で固定せず、**仕事を分ける軸6本**の組み合わせで組み立てる：
  1. クリエイティブ側／オペレーション側
  2. 相手がモノか人か
  3. 繰り返しか一品物か
  4. 判断の手がかり（目／手／耳／味・匂い／相手の反応）
  5. 失敗の重さ（やり直せる／やり直せない・危険）
  6. 段取り主体か手技主体か
- 例：3DP試作＝オペレーション側（設計の段取り含む）／モノ／一品物／目＋手／失敗は軽い／段取り主体。調理＝オペレーション／モノ／繰り返し／味・匂い・目／軽い／手技主体。介護＝オペレーション／人／毎回違う／相手の反応／重い／状況判断主体。
- 実装では Claude Code の **Skills**（分野ごとの知識ファイル）として持つ。

## 7. 題材（決定）：3Dプリントで試作部品を1点作る
- 車の樹脂部品の試作で3DPを使う。それを家庭の3DPに置き換え、作者が自分で手を出せる形にした。勤務先の素材・情報は使わない。熟練者役は作者本人。
- 3段階：**1 設計の段取り**（穴位置、工具が入るか、ボルト締め構造）→ **2 印刷の設定**（向き・角度・サポート・意匠面・壊れやすい向き。不具合が起きやすい状態も再現して残す）→ **3 後処理**（したい加工に対して必要な工具・物・手順）。
- MVPは**オペレーション側が主役**。設計の段取りは「作る前のチェック手順」として取り込む。将来はクリエイティブ側にも対応（データの形は共通）。
- 3DPは B（数値：オーバーハング45°など）と C（体感：当て板で傷を防ぐ）が混ざった題材。AI提案と熟練者の役割分担を見せやすい。

## 8. データの骨格
```
分野プロファイル（3DP試作／調理／介護…）
 └ 案件（試作部品1点：最終的にしたい形・用途）
    └ 段階（1 設計の段取り → 2 印刷の設定 → 3 後処理）
       └ 手順ごとの判断カード（分かれ目1個＝1枚）
          └ 紐づく動画・写真の場面（失敗品の写真、手元映像）
```

## 9. 判断カード（決定。16項目＋分かれ目マーカー）
動画1本からアプリが取り出す「コツ1個ぶんのメモ」。ベテランが書くのではなく、アプリの下書きをベテランが直す。名前は現場に合う言葉（カンコツ、ポイント等）に変えてよい。

| # | 項目 | 判断モデル | 例（ツメの傾けを決める） | 誰が埋めるか |
|---|---|---|---|---|
| 1 | 手順名・段階 | — | ツメの傾けを決める／2 印刷の設定 | アプリが動画から |
| 2 | 注目点（何を見る） | ① | ツメの薄さ、層の向き | アプリが音声から |
| 3 | 正常／異常の境界 | ② | 層の境目がツメの根元に来たら異常 | アプリが音声から／足りなければ聞く |
| 4 | 判断（どうする） | ③ | 15°傾けて印刷する | アプリが音声から |
| 5 | 加減（どのくらい） | ④ | 30°を超えるとサポートが増えるのでそれまで | アプリが音声から／足りなければ聞く |
| 6 | 理由（なぜ） | — | 層の境目で折れる | アプリが音声から／足りなければ聞く |
| 7 | 止める条件／次へ移る条件 | ⑤ | スライサーでサポートがツメに付かなくなったら次へ | アプリが音声から／足りなければ聞く |
| 8 | 素人がやるとどうなる | ⑦ | 置いたまま印刷してツメが根元から折れる | 聞く／AIが下書き・ベテラン確認 |
| 9 | 失敗するとどうなる | — | 折れた写真 | ベテランが写真を足す |
| 10 | 必要な工具・物 | ③ | スライサー、ニッパー、400番ヤスリ、当て板 | アプリが音声から／足りなければ聞く |
| 11 | 判断の種類 | A/B/C/D | B寄りのC | AIが判定、ベテラン確認 |
| 12 | 安全に関わるか | — | いいえ（刃物を使う手順は はい） | 分野プロファイルから判定、ベテラン確認 |
| 13 | さらに良くするには | — | ブリムで反りが減る（確度：高、根拠：…） | AI（確度の高いもののみ） |
| 14 | 出どころ | — | 熟練者の判断／AIの提案（承認済み） | 自動 |
| 15 | 紐づく動画の時刻 | ⑥ | 1:02〜1:30 | 文字起こしの時刻からアプリが自動 |
| 16 | 承認状態 | — | 下書き／承認済み | ベテラン |

**分かれ目マーカー**：素人とベテランで結果が大きく変わるカードに印を付ける（8の対比が大きい、失敗の重さが大きい、ベテランが時間をかけている等から判定し、ベテランが確認）。手順書の中で分かれ目だけ目立たせ、教育モードはここで必ず止まる。

## 10. 知識の出どころ（決定）
- 主役は熟練者の知識（C・D）。AIは下書き・質問・「さらに良くするには」の**確度の高い提案（A・B）**のみ。確度の低いことは出さない（出すなら「未確認」）。
- **安全に関わることは熟練者を優先**。
- 出どころをラベルで区別する（項目14）。熟練者とAIの相乗で、学ぶ人がベテラン以上に育つ可能性もねらう。

## 11. 入力：ベテランは撮るだけ（決定）
- **作業しながら説明をしゃべる動画**が基本。音声の文字起こしがカンコツの主な材料。映像は場面を示す役（物の認識ではなく「なぜ」を読む＝「画像解析」とは違う）。
- アプリが手順に切り分け、判断カードの下書きを作り、読み取れなかった欄だけ短く聞く。承認されたものだけが手順書になる。
- 将来は無言の動画にも対応し、しゃべった分だけ精度が上がる設計。

## 12. 出力：動画で見れる手順書（決定）
- 手順がチェックリスト型に並び、各手順を開くと動画（または写真）が再生され、横に判断カードが出る。
- **参照モード**（中堅・ベテラン）：そのまま引く。
- **教育モード**（新入社員、必須）：分かれ目で動画が止まり「次にどうする？なぜ？」。答えを判断カードと照らして振り返りを返す。「いま止める？まだ？」（項目7）も問える。
- 余裕があれば：「この手順について聞く」窓（承認済みカードを根拠に答える）。主役にはしない。

## 13. UIは2種類、切り替え可能（決定）
作る側はガラケー世代、見る側はZ世代を想定。同じデータを、切り替えボタン1つで行き来。作る場面・見る場面とも切り替え可能。
- **Z世代向け：ショート動画風** — 縦全画面動画、上スワイプで次の手順、要点を字幕のように重ね、タップで「なぜ？」。教育モードでは動画が止まって選択肢。撮る側は縦に撮ってそのまま投稿する感覚。
- **ガラケー世代向け：1画面1操作** — 選ぶものは1〜3個、大きな文字・ボタン、番号付き手順、「次へ」「戻る」は常に同じ場所、縦スクロールとタップだけ。録画ボタン1つ、確認は「合ってる／直す」。目安は「LINEくらいの操作感」。

## 14. 機能一覧
### 残す（ベテラン）
1. **案件を登録**：作る物の説明・写真。分野プロファイルを選ぶ。
2. **撮る**：録画ボタン1つ。作業しながらしゃべる。
3. **読み取り（自動）**：文字起こし → 手順の切り分け → 判断カード16項目の下書き → 分かれ目マーカー → 判断の種類タグ → 足りない欄の質問。
4. **聞き取り**：足りない欄だけ、判断モデル①〜⑦から生成した短い質問（「どうなったら止める？」「素人がやるとどうなる？」）。しゃべって答える。
5. **確認・承認**：カード1枚ずつ「合ってる／直す」。AIの改善提案は「採用／不採用」。失敗写真を足す。
### 使う：参照モード（中堅・ベテラン）
6. **やり方を引く**：案件 → 段階 → カード＋動画の場面。
7. **配分ビュー**：各手順にベテランがかけた時間の割合（項目15から自動）。
8. **自分のやり方と比べる**：「自分ならこうする」との違いを整理（余裕があれば）。
### 使う：教育モード（新入社員）
9. **分かれ目で止めて問う**：「次にどうする？なぜ？」「いま止める？まだ？」。答えをカードと照らして振り返り。
10. **異常状態ライブラリ**：作業前に失敗・異常の写真と言葉を見る（経験の差を疑似的に埋める）。
11. **振り返り**：自分の作業の記録・映像をカードと照らす（余裕があれば）。
### 蓄積して育てる（全員）
12. **次の案件への引き継ぎ**：似た過去カードを提示。「毎回ゼロから」を減らす（余裕があれば）。
13. **数値化の候補**：同じ分かれ目のカードが溜まったら、体感の言葉に数値を紐づけ、C→Bへ昇格を提案（将来。MVPでは「候補」の表示まで）。
14. **分野プロファイルの追加**：Skillを足す＝分野を足す。2例目（調理など）を薄く入れて基盤を証明。
### MVP（3分で見せる太い線）
2 撮る → 3 読み取り → 5 承認 → 6 参照 → 9 教育モード。UI切り替えを見せ場に。7は追加コストが小さいので入れる。8・11・12・13は余裕があれば。

## 15. 使用例（給餌機のフタ部品）
1. ベテランが録画して作業しながらしゃべる。送信して終わり。
2. アプリが文字起こし → 手順に切り分け → カード下書き → 分かれ目マーカー。足りない欄だけ質問を残す。
3. 翌朝5分で確認。「合ってる／直す」、質問にはしゃべって答える。AI提案は「採用」。
4. 新人が教育モードで開く。分かれ目で動画が止まり「どの向きで印刷する？なぜ？」。答えると振り返り。ベテランに聞かずに1個作れる。
5. 中堅は参照モードで必要なカードだけ10秒で引く。

## 18. 決定事項（まとめ）
- テーマ「あなたにしかない深さを」。勤務先の情報・映像は使わない。Streamlit は使わない。
- 題材：3Dプリントで試作部品を1点作る（設計の段取り→印刷の設定→後処理）。熟練者役は作者本人。
- 基盤アプリ：分野プロファイル（仕事を分ける軸6本）で差し替え可能。MVPはオペレーション側が主役。
- 判断モデル：分かれ目の7分解、判断の4種類（A〜D）、蓄積→言語化・数値化。
- 判断カード16項目＋分かれ目マーカー。
- 入力：作業しながらしゃべる動画。文字起こし必須。アプリが読み取り、足りない所だけ聞く。チャットは主役ではない。
- 出力：動画で見れる手順書。参照モード／教育モード（必須）。
- UI：Z世代向けショート動画風／ガラケー世代向け1画面1操作、切り替え可能。
- 知識の出どころ：熟練者が主役。AIは確度の高い提案のみ。安全は熟練者優先。出どころをラベルで区別。
- 公開URLで誰でも触れる形。コードは GitHub 公開リポジトリ。言語は問わない（作者は Python 少し）。
- できた部分から画面録画してデモ素材に。**デモ動画は3分**。
