## テーマ（どちらか1つ）
1. **あなたにしかない深さを** … 仕事・地域・技術・趣味など、自分がよく知る世界から始め、その隣にいる仲間や引き継ぐ人が使うものを作る。 ← 本作品はこちらを想定
2. **本来、誰にでも届くべきものを** … 専門知識・費用・言語・手続きの壁で助けを受けられない人に届ける。

## 審査基準
| 基準 | 配点 | 主な観点 |
|---|---|---|
| インパクト | 30% | 課題の出どころ、困っている人の範囲、ハッカソン後も使われるか |
| デモ | 25% | 冒頭で課題と解決策が伝わるか、前提知識なしで価値が分かるか |
| Claudeの活用 | 25% | 基本利用を超えているか、Claude Codeを開発の中心に置いているか、Skills・サブエージェント・MCP・フックを目的に合わせて選んでいるか |
| 深さと実行力 | 20% | 試行錯誤の跡、設計と実装の丁寧さ、安心して使える形か（**リポジトリを見て判断**） |

## ルール
- デモで見せるものはすべて公開リポジトリに置く。
- 新規開発のみ。キックオフ前に作ったものは使えない（仕様書・構想の事前作成は可）。
- 使用権のないコード・データ・素材は失格。
- 当事者インタビューなどの協力は可。コードを書くのは参加者のみ。
- 提出物はすべて日本語。
- 参加者ガイドの「作らないもの」の例：メンタルヘルスの助言、基本的なRAG、Streamlitアプリ、画像解析、教育向けチャットボット、履歴書の選別、栄養の助言、性格診断、医療の助言
  - 本作品は「画像解析」「教育向けチャットボット」に見えないよう、**暗黙知の聞き取り→熟練者の確認→映像に紐づく教材**の流れを主役にする。

- Claude の使い方に関する質問への回答

### 締切と審査
- 提出締切：**11月8日（日）20:00 JST**。提出フォーム：https://cerebralvalley.ai/e/built-with-claude-japan2026/hackathon/submit
- 11/9 一次審査 → 11/10（火）13:00〜14:00 最終審査（上位6チームの事前収録デモ3分を再生 → 審査員が約2分議論）。**2次も一次と同じ評価軸**。
- **プラットフォーム上ではプロジェクト名を変えられない**（チーム名も提出後は変更不可）。名前は「WAKAREME AI」で決めてから出す。
- 提出後も、ほかの欄（ログイン情報など）は提出データを更新できた例がある。

### 必ず守ること（運営の最終確認リスト）
- GitHub リポジトリは**公開**。
- デモ動画は**3分以内・日本語・誰でも見られる**（YouTube の限定公開など、URLを知っていれば見られる状態）。
- **デモ ＞ プレゼン**：スライドで説明するのではなく、作ったものが実際に動いているところを見せる。数字やデータを見せる場面だけはスライドでよい。画面録画で実際の操作が伝わればよい。
- デモで紹介するのは**期間中（11/2〜11/8）に自分が作った機能・コードだけ**。判別できないと失格。
- 概要は500字以内。冒頭は1文で「このプロジェクトは、〔誰〕の〔課題〕を〔どう変える〕〔形〕です。」
- 審査員用のアプリのリンクがあれば、ログイン情報を書く（任意）。

### ルール（お知らせより）
- 1チーム最大2名（1人でも可）。新規制作のみ（既存プロジェクトの再利用は不可。自分の貢献が区別できないと失格）。
- 法令・倫理・各プラットフォームのポリシー違反、権利のないコード・データ・素材を使うものは失格。
- 作成禁止の例（汎用的なもの）：AIメンタルヘルスアドバイザー／基本的なRAG／Streamlitアプリ／画像解析ツール／「AI for Education」チャットボット／AI履歴書スクリーニング／AI栄養アドバイザー／性格診断／医療アドバイスを行うAI。
  - 本作品の注意：完成品の写真比較は機能の1つで、主役は「熟練者の暗黙知を分かれ目で取り出し、承認して教材にする」流れ。教育モードもチャットボットではなく、並べ替え・安全ポイント・分かれ目のテスト。デモでもこの順で見せる。

### 素材の扱い（質問チャンネルの回答）
- 合成音声のナレーションが一部入っても問題ない（VOICEVOX 等も可。外部の素材は出典をリポジトリに書く）。
- OSS の素材はライセンスを守れば使える（デモの飾りなど）。第三者のスキルは開発の補助ならよいが、プロダクトやリポジトリに入れない。
- 法令・公的な様式や、転載を認めている資料は出典を書けば映してよい（禁止は「権利を有しない素材」）。
- 以前に自分で作った音源などを素材に使うのは可。ただし「以前作ったもの」と明示する。
- 当事者（職人など）の映像を入れる場合は、公開範囲を本人と確認しておく（運営の発表などで公開される可能性がある）。

### 提出フォームの項目（長いので早めに）
1. プロジェクト名（必須・あとで変えられない）
2. 選択したテーマ：「あなたにしかない深さを。」／「本来、誰にでも届くべきものを。」
3. プロジェクト概要（冒頭1文の型＋利用の場面込みで500字以内）
4. 公開 GitHub リポジトリの URL
5. デモ動画の URL（3分以内・アクセス可）
6. 使用した Claude の製品・機能（複数選択）：Claude Code CLI／IDE 拡張／Desktop／Cowork／Claude.ai／Claude API／Managed Agents／Agent SDK／その他
7. 開発中に一番詰まった場面（何を作ろうとしたか → どう指示したか → 何が起きて期待と何が違ったか → どう対処したか）
8. その問題の製品・環境・原因（製品1つ／モデル・Claude Code のバージョン・OS・再現性／主な原因を選択肢から1つ）
9. 開発に必要な公式の情報を十分見つけられたか
10. Claude を使った感想と改善してほしい点（日本語・日本の業務での欠点と利点／他のAIツールとの比較（なければ「比較なし」）／一つだけ直すなら何か、それで何が作れるか）
11. 審査員用リンク・ログイン情報（任意）：本作品は手元の Mac で動かすので、審査員が直接触れるリンクは基本なし。書く場合も本番の管理者IDは書かない。
